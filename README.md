# 裁纸师工作台（Flask + SQLite + Docker Compose）

从一张印张上，按“贯穿整张纸片的横/竖 Guillotine 切刀”尽量多地裁出四边与画框完全重合的完整版画。
支持录入纸张与最多 12 幅互不重叠的矩形画框、给出最多还能裁成几幅及逐刀切序、
登记真实落刀（允许切偏）后按剩余纸片重新排程，并把进度持久化到 SQLite。
落刀切出的空白余纸可原子领用为试印新印张，永久保存源印张/纸片出处，并按规则退回或锁定。

- 坐标：整数毫米，原点在纸张左上角，`y` 向下；画框用 `x, y, 宽 w, 高 h`。
- 刀缝按 **0** 计算。
- 横切 = 水平线，登记 `y`；竖切 = 垂直线，登记 `x`。
- 只有当某张纸片的四条边与某幅画框四条边**分别重合**时，该纸片才记为成品。

## 功能

1. **录入与校验**：纸张宽高、≤12 幅画框；整数校验、越界校验、正面积重叠校验（允许边贴边）；
   首页有动态表格和实时 SVG 预览；无 JS 时原生表单也可提交（错误返回 422 并回显）。
2. **最优排程**：记忆化递归 DP，输出
   - 当前各剩余纸片上“最多还能裁成几幅”及总数；
   - 达到该数量的完整切序，逐刀标明**纸片（编号/临时路径标签与坐标范围）、方向、位置**；
   - 每刀会切到并舍弃哪些画框、最终成品落在哪个临时纸片标签。
   - 优化目标按字典序：① 成品数量最多 → ② 成品总面积最大（同数量时优先舍最小画）→ ③ 刀数最少。
3. **实际落刀登记 + 偏刀续排**：登记真实刀位（可与推荐不同，记录偏差），
   立即把纸片分成两个子纸片、把被刀穿过内部的画框标记为 `ruined`、
   把四边重合的子纸片/画框标记为 `finished/done`，然后基于真实剩余纸片重算。
4. **空白余纸领用 / 出处 / 退回**：
   - 裁切页只对“已由落刀切出（有父纸片）、仍为 `active`、未领用”的余纸显示领用入口；
   - 余纸矩形与源印张**任一画框**有严格正面积重叠即拒绝，`pending/done/ruined` 全状态画框都参与判定，边贴边允许；
   - 领用时按余纸真实宽高进入常用画框录入页并锁定宽高；成功后源纸片变 `claimed`，落刀 API/表单返回 `claimed` 拒绝；
   - 新印张页与 `/jobs/<id>/provenance.json` 可查源印张号、源纸片号、余纸/源纸尺寸和坐标；出处保存在独立 `piece_claims` 快照中，源印张重开或删除后仍可查；
   - 新印张**从未落刀、从未重新开始、源纸片仍为 `claimed`** 时可退回；退回在同一事务中撤销新印张并恢复源纸片为 `active`；
   - 一旦落刀或重开，永久禁止退回（落刀计数跨 reset 保留）；普通删除新印张不等同退回，不会意外释放源纸片；
   - `BEGIN IMMEDIATE` 事务加部分唯一索引 `uq_active_claim_source_piece` 保证同一片源纸片至多一个有效领用；失败领用/退回整笔回滚。
5. **三类落刀拒绝（进度原样保留，不写 cuts/pieces）**：
   - 纸片已裁过并分成两片（`already_split`）；
   - 纸片已是四边重合的成品（`finished`，含状态滞后的几何兜底）；
   - 刀位不在纸片严格内部（`outside`，贴边 `pos==x0/x1` 或越界都拒）。
6. **持久化**：SQLite 五张表 `jobs / frames / pieces / cuts / piece_claims`；
   登记、领用、退回均用 `BEGIN IMMEDIATE` 事务；外键级联；提供“重新开始”和删除印张。
   旧库启动时会自动重建 `pieces` 表以加入 `claimed` 状态。
7. **可视化操作页**：按比例 SVG 画出纸张、当前纸片（#编号、已领用橙色虚线）、画框状态、带序号的推荐刀线；
   统计卡、切序列表、余纸领用卡、出处/退回卡、登记表单（“填入登记”一键带入推荐刀位，可改偏）、当前纸片树、落刀记录。
8. **部署**：`Dockerfile` + `docker-compose.yml`（命名卷 `/data` 持久化 SQLite，带 healthcheck）。

## 用 Docker Compose 启动（推荐）

```bash
docker compose up --build
# 打开 http://localhost:5000
```

SQLite 文件在容器内 `/data/cutting.db`，由命名卷 `cutting-data` 持久化；
`docker compose down` 不丢进度，加 `-v` 才会删卷。

## 本地直接运行（不用 Docker）

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
CUTTING_DB=./cutting.db python app.py        # http://127.0.0.1:5000
# 或 gunicorn --bind 0.0.0.0:5000 app:app
```

运行测试：

```bash
python -m unittest discover -s tests -v
```

## 算法说明

对每张当前活纸片 `R` 独立求解。状态就是矩形 `R`（当前待排画框集合在一次规划内固定，
几何包含即可确定）：

- 若 `R` 与某待排画框四边重合：得 1 幅、0 刀；
- 否则枚举严格位于 `R` 内部的候选刀位——只取内部各画框的 `x0/x1`（竖）、`y0/y1`（横）。
  最优解的有用刀位总能挪到某条画框边而不恶化左右分组，故无需枚举每毫米；
- 刀后两子矩形递归，目标向量 `(数量, 成品面积, -刀数)` 取字典序最优；
- 被刀穿过内部的画框不被任何子矩形完整包含，等价于被舍弃/切坏。

复杂度对 ≤12 框非常小：单纸片可能的边界组合至多约 `(2n+2)^2` 个矩形状态，
每状态枚举 `O(n)` 刀位。

## 内置“必须舍弃小画”示例

首页点 **“必须舍弃小画：风车式五画（100×100）”**：

| 画框 | x,y,w,h | 面积 |
|---|---|---:|
| A 大画 | 0,0,70,55 | 3850 |
| B 大画 | 70,0,30,72 | 2160 |
| C 大画 | 15,72,85,28 | 2380 |
| **小画 D** | 0,55,15,45 | **675** |
| E 中画 | 15,55,55,17 | 935 |

五幅恰好铺满 100×100，且是非切片“风车”布局：任意贯穿竖线都严格处在某幅画的
x 区间内、任意贯穿横线都严格处在某幅画的 y 区间内，所以**不存在不切到任何画的第一刀，
5 幅不可能全出，最多 4 幅**。实测排程第一刀为 `#1 横切 y=72`（该刀穿过小画 D，将其舍弃），
随后 4 刀救出 A/B/C/E。

补充（已用求解器逐一验证）：单舍 A/B/C/D 都能得 4 幅，单舍 E 只能得 3 幅；
在所有“4 幅”方案中，舍 D 保住的总面积 9325 mm² 最大，因此第二目标唯一选中“舍小画 D”。
若只看数量，舍 A/B/C 也是并列最优——这是刻意保留的透明取舍，不是漏算。

## 缺项与限制（如实说明）

1. **本环境没有 docker / docker compose 可执行程序与守护进程，因此 `docker compose up --build`
   未能在这里真正跑一遍**；已验证 compose YAML 合法、Dockerfile 的 gunicorn 启动目标可正常服务。
   首次在有 Docker 的机器上构建时仍可能遇到网络拉镜像/装包问题。
2. 本环境没有 docker / docker compose 可执行程序与守护进程，因此 **`docker compose up --build`
   未能在这里真正跑一遍**；compose 文件未改且已用 PyYAML 解析，Dockerfile 的 gunicorn 目标已实起实测。
   首次在有 Docker 的机器上构建时仍可能遇到网络拉镜像/装包问题。
3. 本次已在临时目录安装 Playwright/Chromium 并补齐用户态系统库，完成真实 Headless Chromium
   点击/提交/弹窗流程与 DOM 断言；但运行镜像缺少中文字体，自动截图里的中文显示为方框，
   因此没有做人眼像素/字体观感确认。功能、布局尺寸和 DOM 文本断言均通过。
4. 实际落刀位置同样只接受**整数毫米**；不支持 `72.5` 这类小数偏刀（题目约定整数 mm，
   若现场需要 0.1mm 可把坐标改成整数“丝米”或引入 Decimal，几何比较需一并改造）。
5. 规划只把“画框边坐标”作为候选刀位（有最优性论证），不会主动给“纯浪费区”安排无意义刀，
   但登记时允许对不含待排画的纸片任意下刀。
6. 面向单个裁纸工位：compose 固定 1 个 gunicorn worker；多 worker/多机并发虽有
   `BEGIN IMMEDIATE` 与领用部分唯一索引兜底，也做过 20 线程抢领检查，但未做正式压测。
   没有用户/权限体系。
7. 没有做撤销单刀（只能整单“重新开始”）、刀缝宽度/刀具补偿、旋转画框等扩展。
   源印张“重新开始”会按既有语义删除旧纸片树，因此未退回的领用将无法再退回；
   出处快照不受影响。若业务要求重开源页仍几何封锁已领区域，需要另加排除区模型。
